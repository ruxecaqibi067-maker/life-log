# 第一版验收方案

版本：v0.1；基线日期：2026-10-22；目标设备：用户的荣耀 200 Pro。

本文定义怎样判断第一版可以交给本人日常使用。2026-10-23 已整合 T01–T16 实现，主机 212 项测试通过，三种构建 Lint 各为 0 错误、13 警告；签名、模拟器和升级阶段证据见 [本轮整体验收报告](releases/0.1.1.md)。

下面的完整 v0.1 矩阵继续保留逐项状态：未取得相应荣耀设备、性能或实际使用证据的用例仍为未执行。模拟器、主机测试和发布候选不能替代荣耀真机或一周自用；不能把阶段接受写成第一版全部通过。

本对话仅负责主管协调、技术方案与独立Git仓库；具体实现由用户另开对话执行。任务分派完成、实现对话报告完成或代码提交完成，均不等于本文验收通过；必须核对该构建的实际证据后更新状态。

## 1. 验收规则

- 状态统一使用：未执行、通过、失败、不适用；不适用必须写明理由。
- P0：数据可靠性与主要记录流程；任一失败不得交付日常使用版本。
- P1：可用性、兼容性、性能与发布检查；交付前通过，或明确列为待修复问题并取得用户对该具体版本的接受。
- 每个用例须留下设备与系统版本、构建版本、实际结果及证据路径；“代码看起来正确”不算通过。
- 使用虚构记录和测试照片，不把真实饮食、作息、锻炼数据或备份包提交进 Git。
- 功能以产品范围文档为准；发生规则变化时同步更新用例，不能仅修改预期结果来掩盖缺陷。

## 9. 性能目标与测量方法

下表是待验证目标，不是已测数据。统一在荣耀真机、非调试连接的release构建、设备温度稳定且无明显后台负载下测量；记录系统版本、数据集与剩余存储。T15可使用技术路线约定的release等效qaRelease候选（debuggable=false、隔离包名与测试签名），T16再用正式release复核；debug计时不能替代。每项10次，保留全部原始耗时；P90采用排序后第9个值（nearest-rank）。

| 指标 | 测量边界 | v0.1目标 | 当前状态 |

| 冷启动 | 应用进程不存在时启动，至首页主要按钮可响应；排除系统首次权限对话框 | P90 ≤ 2秒 | 未执行 |
| 文字/点选保存 | 点击保存或作息按钮，至持久化成功且界面确认；包含数据库写入 | P90 ≤ 300毫秒 | 未执行 |

工程性能与操作负担分开记录：前者用计时结果判断，后者观察从首页完成一次记录的点击步骤。持续一周试用时记下“不想填、找不到、忘了怎么改”等具体场景；漏记不算零运动或零睡眠，也不要求连续打卡。
