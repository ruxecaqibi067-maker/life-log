# 第一版验收方案

版本：v0.1；基线日期：2026-10-22；目标设备：用户的荣耀 200 Pro。

本文定义怎样判断第一版可以交给本人日常使用。2026-10-23 已完成 T01–T07 的主机阶段检查：143 项测试通过，Lint 0 错误、10 警告，debug APK 和设备测试 APK 可构建。范围、原始证据和限制见 [整体验收报告](reviews/T01-T07_INTEGRATION.md)。

下面的完整 v0.1 验收矩阵仍保留逐项执行状态：本轮自动化覆盖不能代替其中的真机操作、未实现训练/备份流程或性能测量。未逐项取得相应设备证据的用例仍标为**未执行**；不得把阶段通过写成第一版全部通过。

本对话仅负责主管协调、技术方案与独立Git仓库；具体实现由用户另开对话执行。任务分派完成、实现对话报告完成或代码提交完成，均不等于本文验收通过；必须核对该构建的实际证据后更新状态。

## 1. 验收规则

- 状态统一使用：未执行、通过、失败、不适用；不适用必须写明理由。
- P0：数据可靠性与主要记录流程；任一失败不得交付日常使用版本。
- P1：可用性、兼容性、性能与发布检查；交付前通过，或明确列为待修复问题并取得用户对该具体版本的接受。
- 每个用例须留下设备与系统版本、构建版本、实际结果及证据路径；“代码看起来正确”不算通过。
- 使用虚构记录和测试照片，不把真实饮食、作息、锻炼数据或备份包提交进 Git。
- 功能以产品范围文档为准；发生规则变化时同步更新用例，不能仅修改预期结果来掩盖缺陷。

工程性能与操作负担分开记录：前者用计时结果判断，后者观察从首页完成一次记录的点击步骤。持续一周试用时记下“不想填、找不到、忘了怎么改”等具体场景；漏记不算零运动或零睡眠，也不要求连续打卡。
