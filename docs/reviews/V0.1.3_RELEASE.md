## 正式签名包覆盖升级

1. 在本轮隔离模拟器安装旧正式包 0.1.2 / code 3，初始不存在同包名安装；通过旧版真实 SAF 预检/确认流程恢复已知虚构 v1 备份，再导出升级前快照。
2. 不卸载、不清除数据，使用 `adb install -r` 覆盖安装 0.1.3 / code 4。签名指纹与旧正式版一致，UID/appId 和首次安装时间保持。
3. 启动新正式包，通过设置和真实 SAF 导出升级后备份；使用 `verify_backup.py --allow-v1-to-v2 --ignore-export-clock` 校验全部清单、计数、记录属性、照片引用及照片字节。

| 数据 | 升级前后比对 |
| --- | --- |
| 饮食 / 作息 / 训练 | 600 / 201 / 200，共 1001 条，保持一致 |
| 运动项目 | 9 个，含自定义项目，保持一致 |
| 训练动作 / 力量组 | 400 / 400，保持一致 |
| 照片 | 200 张，全部 SHA-256 一致 |
| 未结束作息 | 1 条，保留原时间点和未结束状态 |
| 设置 | 主题及其余设置一致；只允许此次真实导出引起的导出时间与对应更新时间变化 |
| 版本变化 | 备份 v1→v2，只增加旧饮食行 `satietyText=null`，不改变旧饱腹感含义 |

发布源最终冻结后再构建并检查交付包，核对源码范围未增加业务改动，复装最终 APK 并复核导出数据。正式下载资产的哈希取最终 `SHA256SUMS.txt`；源码/标签/远端与下载字节的最终核对保存在本地交付凭据。

新版能读取旧 v1 备份；旧 App 不能读取新 v2 备份。上述实验是 API34 模拟器上的正式包覆盖升级，不等同于荣耀或其他品牌的升级验证。
