## 目标保存契约

- 新增 `AppSettings.targetSleepMinutes: Int?`，含义为当前全局每日时长目标；单位为分钟，合法已设置值为 1–1440，null 为尚未设置。目标没有时区语义，也不代表历史每一天的原始期望。
- 首次安装、旧库升级、读取缺少该字段的旧备份均为 null；不替用户自动设置目标。T19 可让编辑器初始建议值为 8 小时，但确认前不能入库。
- Repository 提供目标观察和保存 API，使用既有 `DataResult` 或等价项目错误契约。非法、溢出、非整数或写入失败不能改变原值；如支持清除，null 明确表示未设置。
- 修改目标只更新设置及其更新时间，保留主题、上次成功导出时间等其他字段，不改变任何作息记录、日期归档或就寝起床操作。
- 主题切换、成功导出、恢复设置和快照复制均须保留新增字段；不能因旧构造调用或 copy 逻辑漏传而悄悄清空。

## 今日时长与汇总接口

通过 `AppContainer` 暴露只读汇总 Flow（建议 `SleepSummaryRepository.observe(date)`）和保存目标 API。具体名称可顺应现有代码，但须在交接中固定，T19 直接复用，不再自行写另一套算法。

汇总至少包含日期、目标分钟数、已完成段数、已记录总毫秒数（无已完成记录时为 null）、是否存在全局进行中作息；读取异常沿用明确的失败状态，不能转成空记录。

| 情况 | 规则 |
| --- | --- |
| 今天属于哪一天 | 与 `HomeViewModel.today` 一致，用注入 Clock 和手机时区决定今天；作息归属沿用已保存的 `archiveLocalDate` |
| 跨夜 | 已完成记录归到起床日，整段计入该日；不按午夜拆分，不重新按当前时区迁移旧记录 |
| 午睡/多段 | 累加属于该日的所有已完成区间；使用 UTC 毫秒差，先求和后格式化，保留秒/毫秒精度 |
| 进行中 | 全局进行中状态持续可见，即使开始日是昨天；没有结束时间的区间不混入已完成总量，不后台推算实际睡眠 |
| 没有已完成记录 | 总量为 null、段数为0，表达“暂无已完成记录”；不能推断今天睡了0小时，也不能展示还差完整目标时长 |
| 无目标/加载失败 | 不产生百分比；读取失败与无记录分开表达，支持重试 |
| 超过目标 | 保留真实时长；图表比例由T19封顶，不能篡改总量或产生负剩余时长 |
| 修改/删除/恢复 | Room Flow 自动刷新；修改结束日期后对应日汇总变化，不创建额外汇总表或缓存副本 |

对外展示表示用户记录的就寝至起床时段，沿用现有“卧床时长”口径；不宣称精确入睡时间或睡眠质量，不输出健康评分。当前目标仅服务首页，不扩展历史目标曲线或趋势分析。

## 数据库、备份与恢复

- Room 计划 2→3，导出 schema 3，保留 schema 1/2；显式注册 `MIGRATION_2_3` 添加可空目标列，同时验证旧 1→2→3 链。禁止破坏性回退或先卸载来解决升级。
- 备份计划 formatVersion/dataVersion 3，保留读取 v1/v2；旧版本缺目标按 null。新导出需完整保存目标，并在导入预检时校验类型和范围；不能把非法值当作 null 静默忽略。
- 恢复成功沿用“全部设置与记录覆盖”的语义：旧备份缺目标就恢复为未设置；取消、失败、回滚则保留或恢复原目标及其他数据。不要只在导出加字段而遗漏恢复/回滚。
- 同步相关格式说明与 `scripts/verify_backup.py` 的版本识别和显式迁移比较，保留已有 v1→v2 验证能力；只允许有定义的新增可空字段差异，实际记录变化仍须报错。
