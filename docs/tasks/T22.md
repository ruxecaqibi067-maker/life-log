# T22 待办与21天习惯数据

基线：`ec005a5`，独立工作树`life-log-t22`；数据实现交给T22，主管验收整合，UI交给T23。用户2026-10-26明确新增待办，随后补充“习惯养成过21天后自动消失”。

## 行为与接口

- Room独立保存手动待办、习惯、生成实例与删除墓碑；标题1–120字，日历日期、可选分钟，支持完成/撤销、编辑/删除。
- 默认每天，支持每N天或每周指定星期；周期为开始日到开始日+20，第22天从进行中隐藏并停止生成，保留原待办和完成历史。暂停/漏做不延期，编辑不改写已有实例。
- 只在进入当天、恢复前台/跨日时按需生成当日实例，不批量补造过去或预造未来；同一习惯同一原生成日唯一，删除后不复活。不得要求后台服务、网络、闹钟权限。
- AppContainer.todos提供Repository；读使用真实Room Flow，写遵循现有DataResult与WriteCoordinator，注入Clock/Zone供跨日验证。
- 待办日期是本地日历语义，不因旅行漂移；可选时间为分钟，完成/创建/修改使用真实时间点。

## 数据安全与交付

Room5→6显式迁移，不改schema1–5或已有记录。完整备份导出v6，读取兼容1–5且新列表默认空；预览、计数、恢复、取消、失败回滚均涵盖新表和墓碑。旧备份全量恢复后不残留新版待办。

针对21天边界、频率、重复生成、删除、完成、真实旧schema迁移及备份/回滚做必要检查；不重复完整套件或操作用户手机。T22先提供契约供T23接入，最终提交实现、schema6与交接。中央STATUS/版本由主管维护，不推送或发布APK。
