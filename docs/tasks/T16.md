## 具体工作

- 使用长期稳定签名生成正式 APK，包名不变、versionCode 递增，密钥/密码不写入仓库或命令日志。
- 在 release 构建验证资源、数据库和图片流程，核对与候选版本的实际差异。
- 以同签名旧版本先保存虚构三类记录、照片、自定义项目与未结束作息，再覆盖安装新版本。
- 验证升级后记录、逐组数据、引用、设置与备份恢复可用；不能用 debug→release 签名不匹配替代该实验。
- 在正式release上复核候选性能与资源结果；T15的.qa测试安装不当作正式旧版本，也不需要卸载正式用户数据来测试。
- 交付 APK、SHA-256、版本/提交、安装更新说明、备份恢复说明、已知限制和签名保管记录。

## 检查命令与证据

- 使用实际工程配置运行 `.\gradlew.bat assembleRelease` 和适用的 release 检查；无配置不伪造命令成功。
- 使用已安装 SDK 的 `apksigner verify --verbose --print-certs` 核对签名，不暴露私钥。
- 用 `Get-FileHash -Algorithm SHA256` 记录交付哈希；记录同签名旧→新版本安装/查询命令与数据核对。
- 提供正式构建和真机升级证据；分清首次安装、覆盖升级、独立测试安装与未执行项。
