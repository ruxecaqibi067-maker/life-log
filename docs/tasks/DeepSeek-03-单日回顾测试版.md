完成标志是用户能依次完成三步：输入自己的测试 Key，用内置虚构样例验证连接，再预览并确认发送所选日期的数据，在同一天的回顾页读到一段中文回顾。

## 手机上怎样操作

1. **输入 Key。** 在测试版提供一个遮罩输入框和清除入口，说明 Key 在本次应用进程内有效。输入、切页及预览均保持离线。Key 可以跨页用于本次测试，进程结束后重新输入。使用普通内存状态，避免输入框通过界面状态恢复、日志、崩溃信息、导出或备份保存 Key。
2. **先用样例测试。** 入口标为「用虚构样例测试连接」。展示即将发送给 DeepSeek 的样例，说明会使用用户自己的 API 额度，用户点击确认后发出一次请求。样例直接来自已验收的文件，不读取 Room；返回内容标为样例结果，和用户所选日期的结果分开展示。[虚构样例](../ai-review/daily-example.v1.json)
3. **发送选中的一天。** 在「回顾」选择日期，点「预览 AI 回顾数据」。保留可读摘要和完整 JSON，确认区显示所选日期、接收方 DeepSeek 和费用提示。用户确认后锁定此次请求，连点仅发一次。成功后在当前预览中展示返回的中文正文。取消确认、关闭预览或切换页面均不触发发送。

## 请求与页面状态

- 为测试版使用独立应用 ID，只在支持此功能的测试构建中加入 `android.permission.INTERNET`、Key 入口和发送功能。保持现有正式版本和本机固定交付 APK 的离线行为。隔离包使用自己的本地记录，安装、启动或测试样例时不读取正式包的个人数据。
- 测试构建向固定地址 `POST https://api.deepseek.com/chat/completions` 发送 HTTPS JSON。认证用 `Authorization: Bearer <Key>`，禁用自动重定向，不记录请求头、请求体或响应原文。测试版选用 `deepseek-flash`、`stream: false`、`thinking: {"type":"disabled"}`。成功响应取 `choices[0].message.content`，仅展示完整且非空的正文。模型与接口已于 2026-11-21 对照官方文档核实。[首次调用](https://api-docs.deepseek.com/zh-cn/) · [Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)
- 请求仅含两条消息。`system.content` 精确取协议第 1 节代码块正文，`user.content` 在样例测试中取内置样例，在单日回顾中取 `ReviewViewModel.frozenAiReviewJson(expectedDate)` 返回的字符串。用 JSON 编码器封装消息，在服务端解码消息后应能逐字符还原原文。提示词、样例若需打包为 Android 资源，以测试断言与文档一致。[v1 协议](../ai-review/daily-rules.v1.md)
- 发送、手动重试和显示结果都须关联到具体预览的一次生成。确认框打开后若预览已失效或重新生成，关闭确认并要求重新预览。同一天的两次生成也要区分。只有原预览仍有效时可用原字符串重试，`snapshotAt` 保持原值。切日、数据或目标变化、监听中断、重新生成、收起预览、离页时，清除旧结果并取消对应请求；已经发出的请求可能已到达服务端，晚到的结果必须丢弃。
- 连接设置有限超时，在后台线程执行。请求进行中显示状态，失败后说明用户能做什么。认证失败（401）提示检查 Key，余额不足（402）提示检查余额，限流（429）提示稍后重试，断网、超时和服务端故障提供手动重试；请求格式错误（400/422）提示测试版请求异常。空正文、截断及格式错误均作失败处理。超时后由用户决定是否再发，避免隐式重发产生额外费用。[错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)
- 回顾正文仅在当前页面内存中展示。沿用现有 JSON 白名单、Room v7 和备份格式。发送范围只含前述两条消息；无需照片、自由文本、其他日期、`latest.json`、ZIP 备份或后台任务。
