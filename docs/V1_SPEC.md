# 第一版产品范围与行为约定

范围基线：2026-10-22；首版持续更新。产品名现为「随手记」（2026-10-24）；支持目标为 Android 9 及以上手机，不限品牌，荣耀 200 Pro 为优先实机验证设备。版本和证据以 STATUS.md 为准。

本文是第一版需求基线。实现分派见 [TASKS.md](TASKS.md)，技术方案见 [TECHNICAL_ROADMAP.md](TECHNICAL_ROADMAP.md)，可执行检查见 [ACCEPTANCE.md](ACCEPTANCE.md)。本文描述目标，不能作为已实现证明。

## 1. 目标与原则

把吃饭、就寝起床、锻炼这些生活片段留在一条能回看的时间线上。最小记录足够轻，详细记录由用户自愿补充。

- 饮食拍照或写一句即可保存。
- 就寝与起床分别点一次，时间立刻持久化。
- 运动选择做过的项目即可保存；次数、重量、距离和时长都选填。
- 允许漏记、补记、修改和删除；不要求每日齐全，不设置连续打卡或完成率。
- 没有网络仍能完成全部核心功能；无账号、无服务器依赖。
- 所有成功提示必须发生在记录真正保存之后。

## 2. 页面与入口

两个底部主页面：**今天、回顾**。设置位于页顶次要入口，包含主题、运动项目管理、备份恢复和版本信息。

| 位置 | 内容 | 行为 |
| --- | --- | --- |
| 今天 | 记饮食、准备睡了/起床了、记运动 | 常用操作在易触及位置，作息按钮随持久化状态变化 |
| 今天 | 今日时间线 | 显示照片/文字、就寝区间、一次训练摘要，点开查看或编辑 |
| 回顾 | 日期选择、对应日期时间线 | 快速跳到有记录的日期，区分空白与加载失败 |
| 记录详情 | 完整内容、编辑、删除 | 删除提供撤销或确认，误触不会直接丢记录 |
| 设置 | 项目管理、主题、备份恢复、版本 | 首版仅设置必要项目 |

记录成功返回原页面，立即显示新记录。保存失败保留输入，并提供可理解的重试提示；不得生成空记录或重复记录。

## 3. 饮食

### 3.1 必须实现

- 支持拍照、从相册选择一张照片、输入文字；可以只有照片、只有文字或两者都有。
- 文字为空且没有照片时不能保存；仅选饱腹感也不能生成空饮食记录。
- 文字上限 500 字；前后空白去除后判断是否为空。
- 饱腹感可不选；快捷项为「5分饱、7分饱、9分饱、撑了」，不默认替用户选择。
- 发生时间默认现在，支持完整日期和时间修改；保存时间与发生时间分别保留。
- 可以后补文字/饱腹感、替换或移除照片、补录历史记录。
- 不强制选择早中晚餐，不要求食物重量、营养或热量。

### 3.2 操作标准

从首页进入拍照入口，经系统拍摄确认后可直接保存；文字和饱腹感不能成为必经步骤。图片处理中明确显示状态，图片处理失败时不能假装已存为照片记录。取消系统相机或相册不会新建记录。

## 4. 作息

### 4.1 两种录入方式

1. 「准备睡了」保存完整开始时间；「起床了」补上结束时间。
2. 补录直接填写就寝日期时间和起床日期时间；午睡按相同方式记录。

点按钮立即写入数据库。退出、进程结束、手机重启后，已保存的进行中状态必须恢复；不依赖 App 常驻或屏幕持续计时。

### 4.2 语义和边界

- 显示「就寝时间」「起床时间」「卧床时长/就寝时段」；不宣称精确入睡时间、实际睡眠时长或睡眠质量。
- 同一时刻最多一条进行中的作息；快速连点不能重复开始或重复结束。
- 一天允许多条已完成记录，支持午睡和非规律作息。
- 跨日按真实完整时间点计算。例如 10月21日 23:50 至 10月22日 07:20 为 7小时30分。
- 已完成区间归到起床当天；进行中区间归到开始当天，并在首页一直显示状态，直到结束或撤销。
- 起床后回看当天时能看到完整区间；修改结束日期会重新归档。
- 结束必须晚于开始；区间重叠时提示并阻止保存，便于修正重复补录。
- 明显异常的长区间先提示用户检查，不自行推断或补上起床时间。
- 误点提供撤销/编辑；漏点结束时可以修正实际起床时间。
- 日期时间保留录入时的时区语义。旅行或更改手机时区后，不得悄悄改变已记录的当地日期。

## 5. 运动项目库

### 5.1 内置和自定义

首版内置跑步、卧推、深蹲、硬拉、划船、肩推、俯卧撑、拉伸；这些只是入口名称，不代表推荐训练内容。

自定义项目：名称必填、类型必选。名称去除首尾空白后为 1–40 字；相同类型下的可用项目不重复同名。类型为：

| 类型 | 选填信息 | 示例 |
| --- | --- | --- |
| 有氧 CARDIO | 时长、距离、备注 | 跑步 |
| 力量 STRENGTH | 每组重量与次数、备注 | 卧推、自定义动作 |
| 其他 OTHER | 时长、备注 | 拉伸 |

常用入口优先显示最近用过的项目。新增项目后可立即选择，不需要离开录入流程重新查找。

### 5.2 历史保护

- 支持名称修改、隐藏和重新启用；隐藏项目不在新记录默认列表中出现。
- 已使用项目的类型不原地变更；需要不同类型时新建项目，避免历史含义混乱。
- 历史训练保存项目名称、类型快照；改名不会追溯改写旧记录。
- 首版以隐藏代替物理删除，避免误删项目损坏历史。
- 从未被使用过的自定义项目也属于用户数据，必须进入备份。

## 6. 一次运动记录

- 最少选择一个项目即可保存；有项目但没有任何数值仍是完整记录。
- 一次训练支持多个项目，允许添加、移除和调整显示顺序；相同项目可再次加入。
- 发生日期时间默认现在，可补录；整次训练备注上限 1000 字。
- 跑步可只写时长、只写距离、两者都写或都不写；显示时不得把空值显示成 0。
- 力量可仅记录动作，也可新增若干组；各组的重量与次数均选填，支持组间不同值。
- 提供「复制上一组/重复添加相同组」减少重复输入；快捷添加 3 组时实际保存为 3 个可独立编辑的组。
- 空白占位组不写入数据库；一旦填写，次数必须为正整数，重量允许 0 表示未附加外部重量，不能为负。
- 距离和时长若填写必须大于 0；单位统一展示为 km、分钟、kg、次；内部转换见技术路线。
- 不要求先开计时器，不自动开启 GPS，不强制完整训练表。
- 旋转屏幕或短暂界面重建保留轻量输入；未点保存的表单不承诺跨强制停止或重启恢复。离开有修改的表单应提示放弃，已保存作息状态不受此限制。

## 7. 时间线、编辑与空白

- 三类记录按发生时间合并排序，时间相同以稳定 ID 排序，不能依加载顺序随机变化。
- 作息完成项以结束时间参与当天排序，显示完整开始/结束；进行中项以开始时间排序并标明状态。
- 今天/回顾使用记录保存的当地日期语义；更改当前手机时区不重写旧记录归属。
- 支持三类记录查看、编辑、删除，编辑后及时更新列表与归属日期。
- 无记录显示「这一天还没有记录」，不写「今天没吃饭/没锻炼/睡了0小时」。
- 首版不提供健康评分、训练负荷、趋势结论或饮食与睡眠因果分析。

## 8. 数据与备份

- 正式记录与照片存本机；已保存的饮食照片不能因删除图库原图或系统清理 cache 而丢失。
- 导出为一个 ZIP：版本化 JSON、全部被引用照片、所有自定义项目、历史快照、进行中作息和非敏感偏好。
- 设置页展示最后成功导出时间；手动备份是第一版的数据迁移方法。
- 恢复仅支持**全量替换**，不支持合并。恢复前显示将替换哪些数据和备份记录数量，用户明确确认后才执行。
- 覆盖前自动制作并校验一份回滚备份；失败时不覆盖当前数据。
- 坏包、损坏照片、错误校验、未知必需版本、路径越界、数量超限都应拒绝；不得留下半恢复状态。
- 同一备份重复全量恢复的结果相同，不增加重复记录。
- 导出文件为未加密文件，保存前明确说明「包含生活记录和照片，请自行保管」；首版不增加密码管理。
- 不包含签名密钥、密码、设备标识或调试日志。系统备份行为另见技术路线，不能承诺控制所有厂商换机工具。

## 9. 第一版不做

桌面/锁屏组件、提醒、自动睡眠检测、手环、GPS 路线、云账号/同步、AI 食物识别、热量营养、训练计划、心率、社交、连续打卡、复杂统计和应用商店上架。

## 10. 什么效果算好

以下是待验证的目标，不是当前结果：

| 维度 | 目标 |
| --- | --- |
| 记录负担 | 作息进入首页后一次点击落库；饮食照片确认后无需填其他字段；运动选项目后可直接保存 |
| 反馈与性能 | 荣耀真机冷启动到可操作 P90 ≤2秒；纯文字/点选保存 P90 ≤300毫秒；照片确认后处理保存 P90 ≤2秒 |
| 数据可靠 | 进程结束、重启、原图删除、重复点击、导入失败和覆盖升级的关键用例通过 |
| 可用性 | 深色模式、按钮至少48dp、系统字体放大后主要流程可完成，单手常用操作容易触及 |
| 回顾 | 按日能找到三类记录和照片，不误解缺失或作息时段 |
| 持续使用 | 本人试用一周，能指出操作阻力并修正；不以记录天数或打卡完成率评分 |

性能口径、原始样本与发布门槛以 [ACCEPTANCE.md](ACCEPTANCE.md) 为准。第一版完成必须同时有代码、测试和必要真机证据，文档完成不等于 App 完成。
