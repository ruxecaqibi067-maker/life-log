# T26 运动项目选择页紧凑布局

对应本轮反馈5–6，基线与测试约束见[反馈与分工](FEEDBACK-2026-10-26-第二轮界面与饮食照片.md)。

- 项目名称/类型为左侧紧凑内容，“选择”放右侧，普通字体少独占一行和大块留白；长名和大字体自然换行/按宽度换行，不能截断关键信息或缩小触控目标。
- 修复搜索下“全部项目/最近使用”与“新增项目”的相互贴压或重叠；使用正确间距/布局约束，普通/窄屏/大字体都可达。新增项目入口应简洁，不必占不必要的整行高度。
- 保持搜索、最近使用、选择回填训练、自定义项目新增/编辑/隐藏和历史快照语义，不改训练量/复制/批量逻辑。
- 拥有feature/exercise页面/选择器及必要本包字符串；如果实际选择器位于其他文件，先与主管核定片段。不要修改公共RecordComponents/主题或整个WorkoutScreens的无关表单，不改导航/数据/schema/备份。

编译和现有相关定向检查足够，不新增纯布局镜像测试。**不自行启动模拟器/连接手机/执行设备测试**；列普通/1.5倍字体、长名、筛选/新增/选择的复核清单交主管统一测。提交及`docs/handoffs/T26-运动项目紧凑布局.md`；不改中央STATUS/版本，不推送或发包。
