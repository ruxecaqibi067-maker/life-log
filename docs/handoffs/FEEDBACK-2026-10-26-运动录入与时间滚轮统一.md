| 反馈 | 交付行为 |

| 时区、运动编号等信息过多 | 运动编辑/详情不显示时区；项目选择仅突出名称、类型和选择入口，去掉数据库编号、内置/可用标识、重复选填说明和改名按钮。改名/隐藏/启用仍在设置中的项目管理页可用，隐藏状态在那里明确显示。饮食详情的条件性时区提示也一并移除。数据层仍完整保存时区和 UUID。 |
| 力量录入步骤多 | 新增力量项目默认直接填写“组数 / 每组次数 / 重量”；无需先新增组或逐组重复输入。三项全空时仍能保存做过这个项目，完全不生成训练量。只填次数或重量、未填组数时按1组；组数可填1–100。仅填组数会提示补次数或重量，避免将没有实际数值的组静默丢弃。 |
| 旧记录每组不同 | “逐组调整”保留原有各组编辑/复制/移动/删除能力；已有不同训练量的组自动以逐组模式打开，不会被压成相同值。相同训练量可切回一次填写。输入扩展后仍使用原有独立 WorkoutSet，保留已有组 ID，支持0kg与空重量的区别。 |
| 运动后评价 | 整次训练末尾提供按消耗感由轻到重排列的4个预设及自定义，全部选填；再次点同一项可取消。自定义为1–40字。详情和训练按日列表展示已保存的感觉，不根据训练量推断感觉或热量。 |
| 时间修改不统一 | 以现有作息滚轮为基础提取公共组件，所有修改记录时间的入口统一一次选择年/月/日/时/分，再确认；纯日期筛选使用同款年/月/日滚轮，不额外要求选时间。 |

## 时间入口盘点与给主管的统一结论

这项统一跨越运动模块，应作为全应用交互规范接受，而不只验收某一张运动截图。

| 入口 | 原实现 | 本包实现 | 时间语义 |
| --- | --- | --- | --- |
| 训练新建/编辑的发生时间 | 原生日期弹窗 + 原生时分弹窗，分两次修改 | `RecordTimeChoice` → `RecordDateTimePicker` | 保留记录时区；确认未变的分钟不抹去旧秒/毫秒；明确修改才写新分钟与偏移 |
| 饮食新建/编辑的发生时间 | Compose 日期日历 + 时钟式时间弹窗 | 同一完整日期时间滚轮，一次原子确认 | 保留记录时区；选择重复夏令时时间的偏移随草稿恢复，保存能区分两次同名时间 |
| 作息就寝/起床时间 | 原有 `SleepDateTimePicker` | 兼容入口委托同一个公共滚轮 | 原有手机时区投影、未改端点精确保存、跨夜及重叠校验继续保留 |
| 工作开始/结束时间 | 直接引用睡眠模块的滚轮 | 改为直接引用公共组件 | 原有端点与工作区间、独立目标语义保留 |
| 训练记录/补录的按日筛选 | 原生日期弹窗 | `RecordDatePicker`，仅年月日 | 按保存的当地日期查询，不改历史归属 |
| 回顾页按日筛选 | 原生日期弹窗 | 同款纯日期滚轮 | 取消不改筛选，确认后查询该日；前后日/有记录日期快捷入口继续有效 |

- 公共实现：`ui/components/RecordDateTimePicker.kt`，包括 `RecordDateTimePicker / RecordDatePicker / RecordTimeChoice`；`SleepDateTimePicker.kt` 保留薄兼容入口和既有测试标记，没有复制一套睡眠与运动不同步的实现。
- 月末切换会夹到合法日期（1月31日→2月28/29日），24小时制；弹窗草稿可恢复，正文可滚动，取消/确认区固定；Android9 的原生滚轮明暗主题兼容继续保留。
- 夏令时不存在的当地时间不能确认；重复时间明确选择第一次/第二次，不常驻显示技术时区/偏移字段。
- 本包已检索生产源码，实际页面不再创建 `DatePickerDialog / TimePickerDialog` 或 Compose 日历/时钟式时间选择器。睡眠/工作目标的小时分钟是“时长输入”，不属于发生时间；它们继续使用原有目标输入，不强塞年月日滚轮。文件选择、相机和图库属于系统入口。
- 建议主管整合时将 `docs/UI_STYLE_GUIDE.md` 中早期原生日历/时钟弹窗条目更新为以上公共滚轮规范；本交接提供完整盘点，历史任务交接没有被改写。

- `MealEditorViewModel.onDateTimePicked(local, offset)` 为原子时间事件，偏移进入草稿；旧分别改日期/时分的方法保留用于既有接口/回归。
- `app/build.gradle.kts` 增加可选 `-PdebugTestSuffix=.workoutcheck`，只在显式指定时给debug加隔离包名；默认包名、生产依赖和release签名逻辑不变。工作设备测试只允许明确的 `.t21check` 或 `.workoutcheck` 包写虚构夹具，仍拒绝正式包。
