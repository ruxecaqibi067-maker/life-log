- T19 用既有 `HomeViewModel.today` 的日期调用 `container.sleepSummary.observe(date)`，随 today/retry 切换收集；不要另算“今日”或重写作息求和算法。现有 today 使用注入Clock和手机时区决定当地日期，并在当地午夜更新。
- 汇总无加载首帧；T19在收集前设置loading。`Success` 即使无记录也存在：段数0、总毫秒null；读取异常或缺少设置单行返回 `Failure(DataError(STORAGE))`，不退化为空记录。失败后该次收集结束，重新收集/调用observe可重试；取消正常传播。
- 目标观察只关注目标值，主题/导出更新不会伪造目标变化；其读取异常传播，由调用方表达失败，不能转成null。
- 目标保存只接受 `Int?`：1–1440，null显式清除；非法值返回 `INVALID_NUMBER`，field为 `targetSleepMinutes`。T19解析文本时使用安全整数解析，不用截断强转；取消编辑不调用保存。建议480只是编辑初值，确认且Success后才算设置成功。写入失败沿用STORAGE等既有DataResult错误。
- 汇总按已保存 `archiveLocalDate` 过滤已结束区间，UTC毫秒先差后求和；跨夜整段归起床日、多段累加，不受当前时区改变影响。全局进行中标记独立于所选日期，不把活动区间推算进总量。没有完成记录的null不能显示为0或“还差完整目标”。
- 不产生百分比或健康评分；T19仅在目标和总量均有值时计算图形，图形可封顶但文字保留原毫秒总量；剩余值不得为负。保留“按作息记录计算”的卧床时长口径。
- 单条SQL同时读取设置、完成段数/总量、全局活动状态；Room自动跟随保存、编辑改日、删除和全量恢复刷新，避免多个独立Flow混合成不一致快照。
