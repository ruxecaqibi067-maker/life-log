## 实际行为与口径

1. 从首页进入作息记录页，默认跟随手机今天，只显示起床归档日属于所选日期的记录。选择其他日期用既有公共年月日滚轮，可前一天/后一天或回到今天；选择在编辑返回及页面重建后保留，退出该页重新进入默认今天。
2. 用户已明确选择“按起床日期”。列表复用已保存的archiveLocalDate（完整起床时间点与录入时区导出的起床日期）；未结束的暂列就寝日，结束后由原保存逻辑归到起床日。与首页/回顾归档一致，修改手机时区不会偷偷改历史日期；不修改数据库和旧备份。
3. 列表下增加“当天作息时间分布”：0–24时横轴，着色已完成的真实休息区间，多段/午睡分别标记；跨夜严格在手机当前时区自然日边界裁切。例如25日23点至26日7点，列表归26日，图表为25日23–24点和26日0–7点。
4. “近七天作息分析”为截至所选日期的连续七个自然日，每日同样一条时间轴，可点击行查看当天。真实UTC毫秒先裁切再汇总，23/25小时夏令时日按实际长度定位刻度；重复本地时刻附offset辅助区分。
5. 没有已完成记录显示“暂无已完成时段”，不把空白解释为0小时或没休息。未结束作息只在开始当天的图上用空心点标出起点，注明未结束、不计时长，不后台推算；全天长区间可覆盖整条轴。
6. 图表明确说明按手机当前时区分日，仅分析已完成就寝记录；具有日期、时段和时长的文本语义。品牌色、深浅色、字体和公共卡片沿用现有主题，不增加图表依赖。
7. 补录沿用原编辑器/保存/删除/长区间确认；从历史日期补录时预填所选日期，点击确认前不写库。编辑未改端点保持秒/毫秒精度。保存、改起床日、结束或删除由Room Flow刷新列表和两类图表，读取失败显示错误和重试。

## 修改入口

- `feature/sleep/SleepAnalysis.kt`：只读自然日时段裁切与已保存归档日期投影。
- `SleepHistoryViewModel.kt`：复用RecordRepository.sleeps()，与首页共用today；保存可空日期选择（null跟随今天），前台重新读取手机时区；分析在Default调度器完成，不在Canvas/Composable读取DAO。
- `SleepHistoryScreen.kt` / `SleepAnalysisCards.kt`：单一LazyColumn、公共日期滚轮、当天记录、当天图和七日图。
- `SleepScreen.kt`：移出旧全历史列表，列表隐藏重复的内部归档日期；原作息状态/黑屏/确认逻辑保持。
- `SleepEditorViewModel.kt`与导航：可选sleepDate仅服务新建草稿初始日期；已有编辑不受影响，所有旧无日期调用继续可用。
- 字符串：`res/values/sleep_analysis.xml`，移除不再使用的旧空状态字符串；不改数据层/AppContainer/schema/备份。
