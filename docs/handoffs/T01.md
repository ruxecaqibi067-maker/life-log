## 失败、修复与未解决项

1. Temurin 官方下载出现连接重置；改为 Microsoft 官方 OpenJDK ZIP，已与官方 SHA-256 对比一致。Gradle 官方分发的 GitHub 跳转出现连接重置/超时；使用华为镜像取得相同分发，与官方 SHA-256 一致，再放入 Wrapper 本地缓存。Wrapper 仍保留官方 URL、分发校验值和 URL 校验设置，JAR 也通过官方 SHA-256 校验。
2. SDK 安装器逐文件复制平台资源耗时较长；停止本包安装进程后，目录移动也遇到 `Access to the path ... is denied`。最终用多线程复制补齐完整官方解压包（11,342 个文件，0 失败），重跑 sdkmanager 成功并复核安装列表。详细过程与日志在环境说明，残留暂存目录仅在本机 SDK `.temp` 下。
3. 首次 `lintDebug` 失败，8 项：本机 SDK 路径转义、低于 minSdk 的图标目录限定，以及 6 项版本升级提示。已转义盘符冒号并将图标移到 `mipmap-anydpi`，清除旧空目录。去掉本包自行增加的 `warningsAsErrors=true`，保留所有升级警告可见，不禁用检查、不建 baseline。初次失败：`lint-debug-first-failure.log` / `.txt`；最终 6 项升级警告见上表。
4. 图标目录迁移后的增量构建出现 `resource mipmap/ic_launcher not found`（`icon-move-link-failure.log`）。完整 clean 构建已成功生成并验签 APK；迁移后的资源从头构建通过，不把失败的增量日志当作成功证据。
5. 构建提示 `libandroidx.graphics.path.so` 无法剥离符号，按原样打包；属于当前 Compose 传递依赖的 debug 构建输出，构建成功。未安装 NDK，未验证后续 release 候选的优化/原生库表现。
