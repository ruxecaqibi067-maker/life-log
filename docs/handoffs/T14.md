## 实际交付

- 设置页现在显示上次成功导出时间；提供「导出备份」「从备份恢复」「导出最近的回滚备份」三个入口。导出为未加密 ZIP 的说明在选择保存位置前可见。
- 恢复路径严格分段：SAF 选包 → T12 预检（只写暂存，不碰正式 DB）→ 预览对话框（饮食/作息/训练/动作/组/照片数量、记录时间范围、是否含进行中作息、导出时间、应用版本、全量替换警告、自动回滚备份说明）→ 用户点击「覆盖并恢复」才调用 T13 引擎。取消预览只丢弃暂存。
- 执行中显示真实进度并防重复触发；导出、预检、恢复、回滚导出可取消。恢复取消只保证在提交前生效；若引擎已越过提交点，会显示真实结果而不是伪造取消。
- 结果按引擎事实区分：`FailedBeforeCommit` 显示「恢复未开始，原有数据未改变」；`Committed` 显示恢复完成；`CommittedCleanupPending` 显示「恢复已完成，旧照片清理未完成」并提供重试清理；`RecoveryRequired` 只允许重试恢复检查，不开放写入。
- 成功后设置页可导出本次恢复前的回滚备份；回滚包仍走 T13 的完整校验/导出路径。无可用回滚包时明确提示，不伪造成功。
- 恢复完成后 AppSettings（含主题）与记录由同一个引擎事务替换；今天/回顾依赖既有 Room Flow 自动刷新。新增测试证明已存在的 `HomeViewModel` 在恢复后收到新时间线。
- 关键文件：
  - `feature/settings/BackupRestoreController.kt`：应用级状态机，操作不随页面/ViewModel 销毁而取消；持有预览 token 的内存状态，不持久化。
  - `feature/settings/SettingsRoute.kt`：OpenDocument/CreateDocument SAF 适配。
  - `feature/settings/SettingsScreen.kt`：预览对话框、进度、结果卡片。
  - `feature/settings/SettingsViewModel.kt`：主题、最后导出时间、备份状态委托。
  - `AppContainer.kt` / `MainActivity.kt` / `LifelogNavHost.kt`：接入共享控制器与设置路由。
- 公共接口：`BackupRestoreController.state: StateFlow<BackupRestoreState>`、`export/selectBackup/confirmRestore/cancelCurrent/dismissPreview/dismissResult/exportRollback/refreshRecoveryState/retryRecovery`、`suggestedFileName`。未改 Room schema、备份格式或 T13 引擎 API。
- 偏差与说明：T13 没有暴露「是否存在回滚包」的只读查询，因此「导出最近的回滚备份」入口始终显示；没有回滚包时由引擎返回 `EXPIRED_TOKEN`，界面显示「尚未生成回滚备份，或文件已不可用」。这样避免在 T14 修改恢复引擎接口。若主管希望隐藏该入口，需要在 T13 引擎增加只读查询。
