## 实际行为

1. 首页结束工作、首页起床和睡前黑页起床共用新结束接口。实际经过不足600000ms/300000ms时，在事务中比较完整原行后删除此次活动记录，结束进行中状态；Snackbar提示“睡眠不足10分钟/工作不足5分钟，本次未计入，已取消记录”。同一毫秒内开始又结束也可正常取消；恰好10/5分钟保留。
2. 短记录删除失败时保留原活动行，显示错误，可重试；不能伪报取消成功。时间倒退、非法时区或陈旧页面不删除记录；校验和删除在同一个Room写事务/备份写入屏障内。丢弃后清除本次撤销入口，不留下失效的“撤销结束”。
3. 超过43200000ms（12小时）时不直接结束，显示主动确认：完整开始日期时间、实际结束日期时间和真实时长，并询问是否忘记结束。恰好12小时无需询问；确认保留真实超长记录，不截断到12小时。
4. 确认框可通过公共 `RecordDateTimePicker` 年月日时分滚轮修改实际结束时间。修改草稿和取消选择器不写库；确认框取消/系统返回保留未结束记录。结束时间须晚于开始且不晚于此次主动结束的捕获时间；不因等待确认而延长。选择同一分钟保留原秒/毫秒和重复时刻偏移。
5. 修正后显示新的实际时长；若不足本类别下限，明确提示“确认后将取消这次记录”，确认后同样丢弃，不产生短记录。确认保存失败保留选定的结束时间供重试；重复结束回调不覆盖已捕获时点。正常完成仍可用原安全撤销恢复进行中。
6. 补录/编辑已完成时段也检查下限，过短显示明确错误、保留输入且不保存，不自动删除已有历史行。超过12小时沿用编辑器确认边界，可取消、改时间再保存。进行中草稿没有结束点时不施加最短时长。

## 修改入口与兼容

- `IntervalDurationPolicy`：精确毫秒下限和超长交互策略；不使用显示取整后的分钟/小时比较。
- `RecordRepository.completeSleep` / `WorkRepository.completeWork`：`DataResult<Record?>`，仅事务成功丢弃短活动行时为null；完成正常返回保存行。原低层finish/save默认规则保留，避免改变旧数据读取、恢复、撤销或测试夹具协议。
- `saveSleep/editSleep`、`saveWork/editWork`增加可选 `checkDuration`，两个编辑ViewModel显式开启新交互规则。备份恢复和旧记录没有被悄悄升级为更严格的数据格式。
- `SleepViewModel` / `WorkViewModel`：接收丢弃结果、发出一次提示、保留超长捕获草稿/修正值、保存失败安全重试。
- `ConfirmIntervalEndDialog`：共用主动确认与实际结束滚轮；首页和黑页复用同一逻辑，确认区独立于可滚动正文。根导航增加共用SnackbarHost，保证黑页取消成功返回首页后仍可看见提示。
- `INTERVAL_TOO_SHORT`仅为新增交互错误码。没有改Room实体/DAO/schema/迁移、备份v7/JSON格式、归档规则、时段图算法、权限、依赖、版本号或签名。
- 新规则作用于本次交互写入；已有短记录和合法超长历史不自动删除、改写或重算。没有操作真实用户安装或生活记录。
