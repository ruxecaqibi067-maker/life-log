## 数据字段与备份边界

所有用户对象 ID 均为规范小写 UUID 字符串，调用者用 `RecordIds.newId()` 为草稿生成并保留 ID，重试沿用同一 ID。除固定单行设置/恢复元数据外不使用整数自增主键。以下各表均保存 `createdAtUtcMs` / `updatedAtUtcMs`；编辑保留创建时间，更新时间取当前 Clock 与已有时间的最大值，避免系统时钟回拨产生倒序元数据。

| 表 | v1 主要字段（公共时间戳另见上文） | 关联与约束 |
| --- | --- | --- |
| MealRecord | id、occurredAtUtcMs、zoneId、localDate、text?、satiety?、photoId? | 文字/照片至少一个；photoId → MediaAsset.id，删除 RESTRICT；日期与照片索引 |
| SleepRecord | id、startedAtUtcMs、startZoneId、endedAtUtcMs?、endZoneId?、archiveLocalDate、activeSlot? | 进行中 activeSlot=1，结束为空；唯一索引及派生状态触发器；结束晚于开始 |
| ExerciseDefinition | id、name、normalizedName、type、isBuiltin、isHidden、activeNameKey?、lastUsedAtUtcMs? | available 时 activeNameKey=normalizedName，隐藏时为空；(type,activeNameKey) 唯一，允许多个隐藏同名项 |
| WorkoutSession | id、occurredAtUtcMs、zoneId、localDate、note? | Repository 保证至少一个条目 |
| WorkoutItem | id、sessionId、exerciseId、nameSnapshot、typeSnapshot、sortOrder、durationSeconds?、distanceMeters?、note? | session → 训练，删除 CASCADE；exercise → 定义，删除 RESTRICT；训练内排序唯一 |
| WorkoutSet | id、itemId、sortOrder、weightGrams?、repetitions? | item → 条目，删除 CASCADE；条目内排序唯一；至少一个数值，重量≥0、次数>0 |
| MediaAsset | id、generationId、relativePath、mimeType、width、height、byteSize、sha256 | 相对 filesDir 的 `media/<generationId>/<id>.jpg`；路径唯一；JPEG、合法尺寸、1–8MiB、规范 SHA-256 |
| AppSettings | id=1、themeMode、lastSuccessfulExportAtUtcMs? | 固定单行，触发器阻止其他 id；主题/偏好与记录可在同一恢复事务中替换 |
| RestoreState | id=1、lastCommittedRestoreId? | 固定单行，留给 T13 的内部恢复提交标记；不进入用户备份 |

- 枚举持久化名称固定：`Satiety` = FIVE / SEVEN / NINE / FULL（分别对应 5分饱 / 7分饱 / 9分饱 / 撑了，另有 null）；`ExerciseType` = CARDIO / STRENGTH / OTHER；`ThemeMode` = SYSTEM / LIGHT / DARK。未知枚举不自动映射成其他。
- `activeSlot`、`activeNameKey`、规范名及日期均需由已验证语义重建/核验，未来导入不能信任外部派生值。Room JSON 包含真实表、索引、外键；额外 guard 触发器由 `creationCallback` 安装，**不在 Room schema JSON 的表导出内**，未来显式迁移须保留或重建。
- `SnapshotRepository.read()` 在同一 DB 事务读取三类记录、完整项目库（含未使用/隐藏项）、全部条目/组、被饮食引用的媒体和 AppSettings。排除无引用媒体和 RestoreState，不生成 ZIP/JSON。T11 应映射为独立版本 DTO，不能直接导出本机 absolute path；运行时媒体 generation 路径与 ZIP 的 `media/<photoId>.jpg` 路径不同。
- Room version=1 与未来备份 formatVersion 是独立版本。T11/T12 仍需实现协议、计数/哈希、全包数量/大小限制与导入预检；本包没有实现恢复引擎或宣称备份往返通过。

## 时间、空值与历史规则

- 保存 UTC epoch milliseconds、IANA zoneId 与按该时区派生的 ISO localDate；不会因当前手机时区变化重写历史归属。作息开始/结束可用不同时区；活动按开始日期归档，完成后按结束时区日期归档并按结束时间排序。
- 时长使用 Instant / Duration；夏令时不存在的当地时间拒绝，重复时间必须显式选择有效 offset。重叠检查在事务内排除当前编辑记录，区间相邻可接续。超过 **24 小时**返回 `LONG_INTERVAL_CONFIRMATION`，调用者确认后再传 `confirmLongInterval=true`，不自动补造起床时间。
- 作息 start / finish 幂等；并发开始只得到一个活动项，重复结束返回已保存记录，使用已结束记录的旧 ID 重试不会重新打开。唯一槽位在数据库层约束；作息和项目的写入采用显式 insert/update，避免 upsert 吞掉其他唯一索引冲突。
- `durationSeconds` / `distanceMeters` / `weightGrams` 为可空 Long，次数为可空 Int。未填始终是 null；时长/距离/次数填入时必须>0，重量允许0。`Units` 使用 BigDecimal 精确换算分钟→秒、km→米、kg→克，拒绝非整数存储精度、非法字符串及溢出，不使用 Double 或填补零值。
- 文字去首尾空白后计 Unicode code points：饮食≤500、训练/条目备注≤1000、项目名称1–40。项目同类型可用名称经 NFKC + Locale.ROOT 小写规范化后唯一。
- 每次训练最多100条目，每条目最多100个实际组；纯空占位组被过滤，排序重排为0起连续整数。允许同一项目在一次训练内重复出现，保留各组独立 ID、不同重量/次数及 null。
- 保存训练及全部条目/组为一个事务；项目改名/隐藏不改历史快照。同一条目 ID、同一 exerciseId 的历史编辑继续保留旧快照；明确替换 exerciseId 才捕获新快照。已用项目（包括历史被删除后仍有 lastUsedAt 标记）不能原地改类型。

## Repository 接入摘要

通过 `(application as App).container` 取得以下实例；UI / ViewModel 不直接读写 DAO 或文件。写入返回 `DataResult.Success(value)` 或 `Failure(DataError)`；错误可区分校验、缺失、重复名称/ID、重叠、长区间确认、不可变媒体、存储不足/不可用等，取消异常继续传播。读取为 suspend/Flow，加载异常须由 ViewModel 明确映射，不能当成空白数据。

| 入口 | 主要 API |
| --- | --- |
| `records` | `mealsOn(date)`、`sleepsOn(date)`、`datesWithRecords()`、`activeSleep()`、`observeMeal(id)` / `observeSleep(id)`；`meal(id)` / `sleep(id)`；`saveMeal(draft, preparedPhoto?)`、`deleteMeal(id)`、`startSleep(id,time?,zone?)`、`finishSleep(id,time?,zone?,confirmLongInterval)`、`saveSleep(draft)`、`deleteSleep(id)` |
| `workouts` | `exercises(includeHidden=false)`、`workoutsOn(date)`、`observeWorkout(id)`、`workout(id)`；`saveExercise(draft)`、`setExerciseHidden(id,hidden)`、`saveWorkout(draft)`、`deleteWorkout(id)` |
| `settings` | `settings()` Flow、`setTheme(mode)`、`recordSuccessfulExport(atUtcMs)`（只能在目标文件完整写入并关闭后调用） |
| `snapshots` | `read()` 返回 DataSnapshot，完整库、稳定 ID、历史快照、活动作息及偏好均可读取 |
| `writes` | `withWrite {}` / `withExclusiveAccess {}`；独立操作互斥，同一结构化协程操作通过私有有效租约组合 Repository 调用，无需释放写保护 |

- Repository 写入各自使用 Room 事务。WriteCoordinator 是应用级互斥，**不会把多次 Repository 调用自动变成一个 SQL 事务**；T13 的全量恢复仍须自己执行单个 DB 替换事务。
- T03 可消费设置、日期列表和按日 Flow，替换 T01 的静态启动壳；记录 ID 相同时保持稳定排序，没有内存中的第二套记录列表。
- T04 必须先实际处理/验证图片，再在 `writes.withExclusiveAccess` 内完成正式文件落盘与 `records.saveMeal`。`preparedPhoto` 只校验元数据，**不证明文件已存在**；T02 没有文件 I/O。元数据与饮食引用在同一 DB 事务提交，旧照片不在此处删除。无引用文件/媒体清理还需 T04 在相同写保护下处理，并尊重未来恢复状态。
- T11 可在同一排他范围内 snapshot / 复制照片 / 完整输出 / 更新成功时间；T13 可使用 internal database 与 RestoreState 接入恢复提交点和启动门禁。恢复日志/文件状态检查尚未实现，不应据此声称中断恢复可用。
