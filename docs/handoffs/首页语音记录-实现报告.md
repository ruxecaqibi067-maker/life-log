# 首页语音记录实现报告

日期：2026-11-12（Asia/Shanghai）。本轮在既有 `feat/description-voice-input` worktree 上实现，起点与当前提交 HEAD 均为 `0f03d2c`。本轮不提交、不推送、不合并 main。

## 实现摘要与 UI 配合

- 首页两排快捷入口之间加入一行独立卡片：“说一句，记下来”启动系统语音，“键入文字”直接进入输入页；随原快捷区一起折叠，保留原四入口回调。
- 新增完整预览页：可编辑原文、继续语音、重新解析、切换四类记录及操作、修改结构化字段、取消、确认保存。页面复用 RecordTextField、RecordCard、公共按钮、ErrorState 和 RecordDateTimePicker，沿用主题色、圆角、48dp 触控区、间距、滚动与 IME 处理。
- 原文变化后须重新解析才能保存；显式手改的字段在重新解析时保留。切换记录类型会重新生成该类型草稿，避免保留不适用的旧类型字段。
- 载入项目、绑定进行中目标和保存时禁用重复操作；载入失败有重试入口。保存以预览字段为准，解析、编辑和取消不写 Room。
- 确认开始睡眠后进入原 BedtimeScreen；开始工作后回普通首页。四类结果均调用原有 Repository 写入与校验；新预览由自己的 ViewModel 协调，没有重写数据库逻辑，也没有修改原各编辑页 ViewModel。

## 核心解析与保存规则

1. 纯 Kotlin 规则识别睡眠、工作、饮食、运动；支持中文/阿拉伯数字，半小时、一个半小时、两小时半及小时＋分钟；常见相对日期、明确年月日、上午/下午、凌晨和跨夜起止。
2. “睡了五小时/工作了两小时”只得到时长，不生成起止。用户补一个明确端点后才计算另一个。明确“刚醒/刚结束/到现在”可以建议固定的录入时刻为终点，界面提示核对。参考时刻与时区保存在 SavedStateHandle，重解析及重建不随当前时间漂移。
3. 模糊钟点、非法日期、夏令时重复/不存在时段保留缺失字段并提示滚轮确认。显式起止和口述时长均保留，冲突会在预览提示并阻止保存；不偷偷选择其中一项。已完成区间不能倒置或结束于未来，开始睡眠/工作的未来开始时间也会阻止保存。
4. 饮食提取吃了什么与时间；运动匹配现有可见项目，支持简单跑步别名、时长、公里/米、组数、次数、公斤。未匹配时要求选择现有项目，不创建项目；力量/有氧/其他数量约束继续由原 Repository 校验。未识别的运动描述仍保留在备注与原文，用户应核对数量。
5. 同时包含不同记录类型、多个运动项目、重复独立记录表达或多个起止区间时提示拆开录入。此为有限规则语法，不宣称支持任意自然语言；复杂表达可修改原文或直接填预览字段。待办/习惯不属于本轮首页解析范围。
6. “准备睡了/开始工作”等是开始操作预览；“我醒了/结束工作”等是结束预览。结束绑定当时的进行中记录 ID/版本，保存时再核对，并使用 Repository 的 expected 行比较；不存在或变化时拒绝结束，不创建假起点，不结束另一条记录。
7. 单次操作 UUID 在草稿中固定；busy/done 防重复点击。请求在编辑、重新解析、返回或保存时失效，语音结果复用上一轮每请求独立令牌、先消费再回写的机制。进程在提交与成功确认之间中断时，重建先核对该操作是否已落库，避免重新编辑或重复插入已确认结果。
8. 原字数、数字、重叠、异常长区间二次确认、结束日归档、ZIP 与自动 JSON 格式保持原规则。未改变 Room schema、版本号、Manifest、权限、依赖、AppContainer、中央 STATUS 或发布内容。没有云模型、营养推算或自动修改历史记录。
9. 系统识别不硬编码 Google 服务，未新增录音/网络权限或音频文件。服务是否可用、是否联网仍由设备提供方决定；“优先离线”不保证离线。服务失败时可继续键入文字。
