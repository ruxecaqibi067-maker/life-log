## 实际交付

- 力量动作仍可零组保存。新选择动作不带入历史训练量，不自动新增组。
- 每个动作下可「新增一组」、编辑独立重量/次数、删除组、上移/下移组；组有稳定 UUID，删除中间组只重排剩余组，不改变其身份。
- 每行提供「再加一组相同的」，另有「复制上一组」。复制插在来源组之后，分配全新 UUID，后续修改与来源独立；不会自动查询或套用上一场历史值。空白来源不执行复制。
- 「添加3个空白组」只创建三个可独立编辑的占位行，不虚构完成量；全部留空时不入库，填完三行后实际保存三个组。
- 重量显示/输入 kg，保存为整数克，十进制精确转换，不使用浮点数。支持精确到 0.001 kg；额外小数位只有不损失精度时可接受。重量允许 0 表示未附加外部重量，留空表示未记录，两者保持区别。
- 次数可留空，填写后必须为正整数；允许只填次数或只填重量。负值、零次数、非法字符、指数形式、无法表示为整数克的小数及溢出均拒绝。重量/次数均空白（含空格）的行不会保存。
- 编辑时保留原记录、动作快照、item/set ID、组顺序及完整时间语义。离开放弃不会写库；保存失败保留原始输入和 ID，可以重试；写入期间及完成后拒绝重复保存和组修改。
- 未完成/非法数值文本使用轻量表单保存，重建后仍可修改；错误能定位到具体重复动作的具体组，两项输入显示错误状态。未保存表单不承诺跨强停/重启恢复。
- 每个组作为外层 LazyColumn 的独立条目，避免一个动作一次创建全部输入组件或引入嵌套纵向列表。新增/复制入口上限为每动作 100 个编辑行（含空白）；数据库继续按最多 100 个非空组校验。达到上限时批量添加整体拒绝，不部分新增。

## 数据与接口

- 沿用 T02 的 `WorkoutSet(id, itemId, sortOrder, weightGrams?, repetitions?, createdAtUtcMs, updatedAtUtcMs)`；持久化模型、DAO、Repository、Room v1 schema、备份格式和版本均未改动。没有新增权限、生产依赖、导航或 AppContainer 参数。
- UI 中 `WorkoutItemForm.sets` 从 T08 的 `List<WorkoutSetDraft>` 调整为 `List<WorkoutSetForm>`，每组仍是独立结构，字段为 `id/kilograms/repetitions`。这是保存未完成和非法输入所需的展示层调整，没有用汇总字符串替代组模型。`WorkoutSetForm.draft()` 经已有 `Units.kilogramsToGrams/repetitions` 转为 `WorkoutSetDraft`。
- `WorkoutSetForm.from(WorkoutSetDraft)` 用于持久化值转输入；`saved/restore` 保存原始文本，`restore` 也识别 T08 的 `weight/reps` Bundle 字段，保留 0 与 null 的区别。原 `WorkoutForm.saved/restore/from/draft` 入口继续可用。
- 新事件：`addSets(itemId, count = 1)`（count 为 1–3）、`changeSetWeight(itemId, setId, text)`、`changeSetRepetitions(...)`、`copySet(itemId, setId)`、`copyLastSet(itemId)`、`removeSet(...)`、`moveSet(itemId, setId, delta)`。均按 item ID 区分同名/重复动作，按 set ID 保留每组身份；只允许编辑力量动作。
- `WorkoutEditorState` 增加 `errorSetId`，与 `errorItemId/error` 一起定位；`change` 清除旧错误。既有新增/排序动作和保存事件保持原入口。
- 所有正式保存仍只调用 `WorkoutRepository.saveWorkout(WorkoutDraft)`，通过既有 `WriteCoordinator` 与 Room 事务统一写入 session/items/sets/最近使用。Repository 剔除纯空组、规范 sortOrder 并保留已有组创建时间；本包不单独直写组表。
