## 实际交付

### 用户可见行为

- **今天**：保留饮食、作息、运动三个快捷入口；首页顶部仍显示全局未结束作息状态（独立于日期，跨午夜不丢失）；其下为当天统一时间线。T05 的仅饮食列表和 T08 的“今日训练”子列表已移除，避免两套列表语义不一致。
- **回顾**：日期栏支持系统日期选择器、前一天/后一天、回到今天和“有记录的日期”快捷跳转；加载、读取失败和空日期分别显示，不把空日期写成“今天没吃饭/没运动/睡了0小时”。点击任一记录进入既有详情/编辑/删除页面。
- **记录跳转**：饮食 → 饮食详情（可编辑、确认删除）；作息 → 编辑作息（可改起止、时区、删除）；训练 → 训练详情（可编辑、确认删除）。没有新增路由，复用 T05/T06/T08 的稳定路由。
- **摘要**：只统计已保存事实；没有记录的类别不显示 0。训练同时区分“场”和“动作”，例如“饮食 1 条 · 作息 1 段 · 训练 1 场 · 2 个动作”。
- **图片**：时间线使用 LazyColumn 和稳定 key；饮食缩略图仅在该行实际组合时通过 `PhotoStorage.photoUri` 解析并校验，然后交给 Coil 异步加载。加载中显示占位图标，失败显示损坏图标，不预加载整日照片，也不让单张图片错误拖垮时间线。

### 排序、日期与刷新规则

- 三类记录按 `sortUtcMs` 倒序排列：饮食/训练用其发生时间；作息完成项用起床时间，未结束项用开始时间。
- 时间相同时先按记录 ID 升序，再按类型限定键（`meal:`/`sleep:`/`workout:`）排序；Room 重新发射不会改变顺序。
- 日期归属完全取保存值：`MealRecord.localDate`、`SleepRecord.archiveLocalDate`、`WorkoutSession.localDate`。完成作息按起床当地日期归档；未结束作息按开始当地日期归档；当前手机时区变化不重写历史归属。
- 改日期后由既有 Repository 写入新的保存日期，今天/回顾的 Room Flow 自动重新查询，记录从旧日期消失并在新日期出现，不保留第二份 UI 时间线，也不重复显示。
- `HomeViewModel.today` 使用注入的 Clock/Zone，按本地午夜重新发射；延迟按 DST 正确计算到下一个本地午夜，不做每分钟轮询。页面返回时 Room Flow 与 Eagerly 状态自动刷新，无需手工 reload。
- 未结束作息同时出现在全局状态卡和“当天时间线”（若开始日就是当天）；这是同一保存记录的两个用途，不是两条记录。完成后只按起床日进入时间线。

主机覆盖要点：

- 首页时间线实际顺序为 18:00 训练、12:10 饮食、07:10 起床；跨日作息只出现一次，摘要为“饮食 1 条 · 作息 1 段 · 训练 1 场 · 2 个动作”。
- 时间线行点击后分别进入饮食详情、编辑作息、训练详情，返回后时间线仍在，数据来自 Room。
- 回顾通过“有记录的日期”跳到 2026-10-22，显示当天饮食；再前进到空日期显示“这一天还没有记录”；“回到今天”恢复。
- 将作息改为 2026-10-20T23:50 → 2026-10-21T07:10 后，数据库仅 1 条作息且 `archiveLocalDate=2026-10-21`；2026-10-23 时间线不再有该行，回到 10-21 显示“卧床 7小时20分”。
- 空日期、加载和读取失败在 ViewModel 层分别验证；失败不会被当成“这一天还没有记录”。

失败与修复记录：

1. `TimelineRepositoryTest` 首轮把 2026-10-22 当成空日期，但该测试的作息结束在 2026-10-22 07:10，实际归 10-22；这是测试夹具错误，修正为检查 2026-10-20 为空。业务实现未放宽。
2. 导航冒烟测试因回顾页新增“今天”按钮与底部“今天”标签同名，`onNodeWithText` 命中两个节点；将回顾按钮改为“回到今天”，既消除歧义也明确语义。
3. UI 测试最初用精确文本断言“卧床 7小时20分”，但该文案与起止时间在同一行拼接；改为 `substring=true`，并保留精确匹配用于行标题。
4. 图片在 teardown 关闭数据库后仍可能被 `produceState` 解析；在时间线行内把图片解析异常转换为行级 `MISSING_PHOTO`，避免单张图片/已删除文件导致时间线崩溃。测试同时在 teardown 前调用 `waitForIdle()`。
5. Lint 发现 `workout_today` 在移除旧首页训练子列表后不再使用；删除该字符串，最终保持 10 项基线警告。
