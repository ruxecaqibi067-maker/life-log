## T21稳定入口

通过 `AppContainer` 获取 `work: WorkRepository`、`workSummary: WorkSummaryRepository`、原 `settings: SettingsRepository`。WorkRecord在 `data.local.entity`，WorkDraft/WorkSummary在 `domain`。方法准确签名如下（默认时点在调用时捕获）：

```kotlin
// WorkRepository；均为suspend写接口，沿用DataResult、WriteCoordinator恢复屏障及Room事务。
suspend fun startWork(id: String, startedAtUtcMs: Long = clock.millis(),
    zoneId: String = zoneIdProvider().id): DataResult<WorkRecord>
suspend fun finishWork(id: String, endedAtUtcMs: Long = clock.millis(),
    zoneId: String = zoneIdProvider().id, confirmLongInterval: Boolean = false,
    expected: WorkRecord? = null): DataResult<WorkRecord>
suspend fun saveWork(draft: WorkDraft): DataResult<WorkRecord>
suspend fun editWork(draft: WorkDraft, expected: WorkRecord): DataResult<WorkRecord>
suspend fun deleteWork(expected: WorkRecord): DataResult<Boolean>
suspend fun deleteWork(id: String): DataResult<Boolean>
suspend fun undoWork(expected: WorkRecord, previous: WorkRecord?): DataResult<Unit>
suspend fun restoreDeletedWork(deleted: WorkRecord): DataResult<WorkRecord>

fun worksOn(date: String): Flow<List<WorkRecord>>
fun works(): Flow<List<WorkRecord>>
fun activeWork(): Flow<WorkRecord?>
fun datesWithRecords(): Flow<List<String>>
fun observeWork(id: String): Flow<WorkRecord?>
suspend fun work(id: String): WorkRecord?

// SettingsRepository
fun targetWorkMinutes(): Flow<Int?>
suspend fun setTargetWorkMinutes(minutes: Int?): DataResult<AppSettings>

// WorkSummaryRepository
fun observe(date: LocalDate): Flow<DataResult<WorkSummary>>

data class WorkDraft(val id: String, val startedAtUtcMs: Long, val startZoneId: String,
    val endedAtUtcMs: Long? = null, val endZoneId: String? = null,
    val confirmLongInterval: Boolean = false)
data class WorkSummary(val date: LocalDate, val targetWorkMinutes: Int?,
    val completedSegmentCount: Int, val recordedDurationMs: Long?, val hasActiveWork: Boolean)
```

- 界面新操作生成规范UUID并保留至重试结束。开始时已有活动项返回该项；同一已结束ID的重试不会重新打开。结束重复调用保留首次已保存结束点；传expected时先比较完整原行，陈旧记录返回NOT_FOUND。
- `saveWork`为补录/直接保存接口，允许按ID更新；页面修改使用 `editWork(draft, expected)`，确认删除使用 `deleteWork(expected)`，避免旧页面覆盖并发修改。ID删除重载供无需比较的显式操作使用，页面优先完整行版本。
- 开始撤销用 `undoWork(savedStart, null)`；结束撤销用 `undoWork(savedFinish, beforeFinish)`，前值必须是相同ID的未结束行。均先比较当前行，恢复开放区间时重新检查重叠；有后续工作时可能拒绝，不能强行覆盖。删除撤销用 `restoreDeletedWork(deleted)`，仅ID仍缺失且区间仍合法时恢复，保留原创建时间。
- UTC区间结束必须大于开始，差值须能用Long精确表示；相邻边界允许相接，工作之间重叠返回 `OVERLAPPING_WORK`。无效区间/时区沿用INVALID_INTERVAL/INVALID_TIME_ZONE，工作和睡眠不跨表互斥。写入失败保留原行。
- 超24小时返回 `LONG_INTERVAL_CONFIRMATION`，恰24小时无需确认。T21应保存最初 `(id, endedAtUtcMs, zoneId, expected)`，用户确认后以同一时点和时区、`confirmLongInterval=true`重试；不要在确认时重新取当前时刻。取消不写库。
- 原始记录Flow和目标Flow读取异常会传播；调用方显示错误，不能catch后emit空列表/null。`work(id)`是直接读取，同样需处理读取异常。普通写失败使用既有STORAGE/STORAGE_FULL/STORAGE_UNAVAILABLE等DataResult错误，协程取消正常传播。
- Room即唯一来源；不依赖页面计时、常驻服务或黑屏。T21用工作日期Flow与原三类日期合并，再统一新增TimelineKind.WORK/TimelineEntry.Work及所有穷尽分支。

## 目标、汇总与日期口径

- 工作目标是当前全局每日分钟数，1–1440，初始/旧库升级/旧备份缺值均null；`null`显式清除。非法Int返回 `INVALID_NUMBER`，field为 `targetWorkMinutes`，不改变原值。页面文本用 `toIntOrNull`等安全解析，不做溢出截断。480只是允许的编辑建议，确认保存Success才生效。
- 设置写入复制整行，只改工作目标和更新时间；主题、导出时间、睡眠目标和原记录不变，睡眠设置写入也保留工作目标。
- 进行中按开始时区的开始日存档；完成整段按结束时区的结束日存档，跨午夜不分摊。旧记录不会随当前手机时区变化重新归档，保留原毫秒时间点。一天可多段，不自动扣午休，无暂停状态。
- 与 `HomeViewModel.today` 使用相同LocalDate输入。单条SQL快照同时读取工作目标、归属日已完成段数/总毫秒和全局活动状态；不合并独立设置/记录Flow，不保存第二份汇总。修改改日、结束、删除和全量恢复会刷新。
- 没有完成段：Success、段数0、总量null；全局活动项即使不属于所选日仍置hasActiveWork=true，不把进行中加入总量。多段先求UTC毫秒差再加总，超过目标保留真实值，不输出评分或百分比。
- 汇总是冷Flow，无加载首帧；消费者在收集前设loading。缺设置单行或读取失败返回 `Failure(DataError(STORAGE))`，该次收集结束；以today/retry重新收集或重新observe重试。无记录不能显示为0小时或读取失败。取消正常传播。
